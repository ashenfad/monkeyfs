## [Unreleased]

### Fixed
- **Overlapping `patch()` contexts no longer un-patch each other**: `patch()` saved and restored `tempfile.tempdir` and shutil's `_use_fd_functions`, `_HAS_FCOPYFILE`, `_USE_CP_SENDFILE`, `_USE_CP_COPY_FILE_RANGE` and (3.14+) `_rmtree_impl` in local variables, as if they were per-context like `current_fs`. They are not -- shutil and tempfile read them from their own module namespace, so they are process-global. Two overlapping contexts (concurrent threads, or async tasks in different contexts) therefore had the second one save the *already-patched* values, and the first one to exit restored the originals while the second was still live: that context silently regained shutil's fd-based code paths, where `rmtree` traverses by file descriptor and no longer routes through the active filesystem. Interleaved exits also left the patched values installed process-wide after the last context was gone. The shims are now reference counted under a lock -- the first entry saves the originals, the last exit restores them -- so they hold for as long as any context is live. Because they remain process-global, they are also visible to code running outside `patch()` while another context is active; noted in the docs. `tempfile.tempdir` is cleared only on the first entry, since `tempfile.gettempdir()` caches its answer back into that slot -- clearing it on a later entry would discard a value an already-live context had resolved, and the later exit returns early rather than putting it back.
- **`shutil.rmtree()` no longer dies on a nested directory**: `MockDirEntry`, the stand-in `patch()` yields from `os.scandir()`, never defined `is_junction()`. CPython 3.12 added a junction check to `shutil._rmtree_unsafe` -- `if is_dir and not entry.is_junction()` -- which runs for every entry rmtree has decided is a directory, so `shutil.rmtree()` on any filesystem tree containing a subdirectory raised `AttributeError: 'MockDirEntry' object has no attribute 'is_junction'` and removed nothing. This was squarely on the path monkeyfs steers callers onto, since `patch()` deliberately clears `shutil._use_fd_functions` to force exactly that string-path implementation; only flat directories, which never reach the check, worked. `MockDirEntry.is_junction()` now returns `False` unconditionally: a junction is a Windows NTFS construct rather than a symlink, and the real `os.DirEntry.is_junction()` answers `False` on every non-Windows platform and for anything that is not one. Defined on all supported versions -- nothing before 3.12 calls it.
- **`shutil.rmtree()` no longer deletes through a symlink**: With the `AttributeError` above out of the way, rmtree ran to completion for the first time -- and walked straight through symlinks. `MockDirEntry.is_symlink()` was hardcoded `False` and `is_dir()`/`is_file()`/`stat()` accepted `follow_symlinks=` and ignored it, so every link described its *target* and a link to a directory was indistinguishable from a directory. `shutil._rmtree_unsafe` recurses on exactly `entry.is_dir(follow_symlinks=False) and not entry.is_junction()`, so `rmtree("/tree")` on a tree containing `tree/inward -> sibling` descended into the link and deleted `sibling` and everything in it -- a directory the caller never named, inside the sandbox but outside the subtree being removed. The missing `is_junction()` had been acting as an accidental interlock: the crash is what kept rmtree from reaching the deletion. Entries now report link-ness, taken from the backend's `islink()` at the moment `os.scandir()` produces them (`os.DirEntry` likewise answers from what it captured, and holding a reference to the filesystem instead would keep the backend alive past the `patch()` context and let one entry answer from two different moments). `follow_symlinks=False` is honored on `is_dir()`, `is_file()` and `stat()`: a symlink is neither a directory nor a file, whatever it points at. `is_junction()` still answers `False` unconditionally -- a junction is a Windows NTFS construct and there is no junction concept in the protocol. Backends without an `islink()` -- it is one of the optional methods -- report no links and behave exactly as before; `VirtualFS` and `MountFS` refuse `symlink()` outright, so nothing changes for them.
- **`os.remove()` on a symlink no longer deletes the target**: `IsolatedFS.remove()` resolved the path first, so `os.remove("link")` unlinked whatever the link pointed at and left the link in place -- `unlink()` never follows the final component. This was the second half of the rmtree data loss: once rmtree correctly declines to recurse into a symlinked directory it unlinks the link instead, and a resolving `remove()` turned that right back into the deletion of a tree outside the one being removed. The final component is now left unresolved when it is a link; the parent directory is still resolved and boundary-checked, so confinement is unchanged.
- **`os.lstat()` no longer answers for the link's target**: `os.lstat()` delegated to `os.stat()`, and `os.stat()` dropped `follow_symlinks=`, so `Path.is_symlink()` was `False` for every symlink and `shutil.copystat()` read the target's metadata. No backend exposes an `lstat()`, so the result for a link is synthesized: `S_IFLNK` for the file type and the target string's length for `st_size`, with timestamps, uid and gid borrowed from the target because the link's own are unreachable. When the link target cannot be read at all -- a link pointing out of the sandbox, a backend with no `readlink()` -- the call falls back to following the link, so confinement errors surface as before. `os.stat()` (following, the default) is unchanged. Also registers the patched `os.stat` in `os.supports_follow_symlinks`: `shutil.copystat()` membership-tests the function object it finds in `os`, and after patching that object is the shim, so copystat was substituting a no-op that returns `None` and then dying on `st.st_mode` -- reachable from `copytree(symlinks=True)` for every link it recreates.
- **`copy2()`, `copytree()` and `Path.touch()` work on an isolated root**: `utime()` was the one method the patch layer dispatches to that `IsolatedFS` never implemented, so `os.utime()`, `Path.touch()` on an existing file, and everything built on `shutil.copystat()` -- `copy2()`, `copytree()` -- raised `NotImplementedError: IsolatedFS does not implement utime()` against an isolated root.
- **`os.chflags()` is refused instead of reaching the host**: BSD file flags are not part of the `FileSystem` protocol and `os.chflags()` was left unpatched, so on macOS it took a virtual path straight to the real filesystem, where it means a different file or none at all. It now raises `OSError(errno.ENOTSUP)` while a filesystem is active, which is both accurate and the one errno `shutil.copystat()` is written to tolerate -- copystat calls it for every symlink `copytree(symlinks=True)` recreates and re-raises anything else.
- **Extended attributes no longer reach the host**: The four xattr functions -- `os.listxattr()`, `os.getxattr()`, `os.setxattr()`, `os.removexattr()` -- were left unpatched, so under an active filesystem they carried a virtual path straight to the real one. They exist on Linux only, and `shutil.copystat()` reaches them through `_copyxattr()`, which CPython defines only when `os.listxattr` exists and degrades to a no-op `pass` everywhere else -- so on macOS the whole path is unreachable and the escape was invisible. The `utime()` fix above is what exposed it: with `copystat()` no longer dying on `NotImplementedError`, `_copyxattr()` ran for the first time and `os.listxattr("/src.txt")` raised `ENOENT` from the host, which it does not tolerate -- taking out `shutil.copy2()` and `shutil.copytree()` on Linux CI for every supported Python. The shims now answer as a filesystem holding no extended attributes does: `listxattr()` returns `[]` (true -- there are none, and it leaves the copy loop nothing to iterate), `getxattr()` raises `ENODATA` (consistent with that empty listing), and `setxattr()`/`removexattr()` raise `ENOTSUP`, because a write has to fail loudly rather than report success no backend can honor. Every one of those errnos is in the set `shutil._copyxattr()` swallows on 3.10 through 3.14, as is the set `pathlib`'s 3.14 `Path.copy()` tolerates. None of the four consults the active filesystem or falls back to the host.

## [0.1.6] - 2026-08-04

### Fixed
- **`VirtualFS.open()` update modes**: `r+` and `rb+` now support reading and persist in-place writes instead of silently discarding them.
- **Safe system path boundaries**: Read-only host passthrough now requires an actual path relationship, so a trusted path such as `/usr/local` no longer also trusts prefix-sharing siblings such as `/usr/local-private`.
- **`bytes` and `os.PathLike` paths no longer bypass interception**: `open()` and `os.open()` matched only `str` and `pathlib.Path`, so any other path type the stdlib accepts skipped the filesystem entirely and reached the host -- `open(b"/etc/passwd").read()` was a plain read bypass, and a bytes write landed on the real filesystem. Paths are now normalized with `os.fsdecode()` before routing, so `bytes` and non-`Path` `os.PathLike` arguments resolve against the active filesystem like any other path. Non-path arguments (file descriptors) still fall through unchanged.
- **Safe-path passthrough no longer hands out host directory fds**: Read-only opens on safe system paths return a real host fd, which for a directory is a durable capability that outlives the safe-path check that granted it -- and was the only way to obtain the fd that made the `dir_fd` escape below reachable. `os.open()` on a directory now raises `IsADirectoryError` while a filesystem is active. File reads through the safe-path fallback are unchanged, as are `os.listdir()` and `os.scandir()`.
- **`dir_fd` no longer escapes the filesystem boundary**: `os.rmdir()` and `os.open()` honored a `dir_fd`, resolving against the host filesystem and bypassing the active filesystem entirely -- including `os.open`'s safe-path and write filters, since its `dir_fd` branch ran ahead of both. A real directory fd is obtainable from inside a patched context via the read-only safe-system-path passthrough, so this chained into arbitrary host reads and writes. Every other patched operation silently dropped `dir_fd`, retargeting the call at a different directory than the caller named. Both behaviors are now replaced by `OSError(errno.ENOTSUP)` for `dir_fd`, `src_dir_fd`, and `dst_dir_fd` across all patched operations while a filesystem is active; outside `patch()`, `dir_fd` is unaffected.
- **Patched `os.mkdir` no longer forwards `mode`**: The `FileSystem` protocol declares `mkdir(path, parents, exist_ok)`, but the patch layer passed an undeclared `mode=` kwarg, so any backend implementing the interface as documented raised `TypeError` on `os.mkdir()` / `Path.mkdir()`. `mode` is now dropped at the patch boundary, matching what `os.makedirs` already did. `VirtualFS.mkdir()` drops its unused `mode` parameter; `IsolatedFS.mkdir()` keeps it for direct calls, but directories created through patched `os.mkdir` now get default permissions instead of the caller's requested mode.

## [0.1.5] - 2026-07-06

### Added
- **`VirtualFS.invalidate()`**: Public API to drop the lazy dir/metadata/size caches after the backing state mutates externally (e.g. a versioned store rolled back underneath a live instance). Replaces reaching into private attributes.

### Fixed
- **Unclosed `VirtualFile` data loss**: `VirtualFile` gains `__del__` — buffered content now persists at garbage collection with a `ResourceWarning`, matching real file semantics. Previously `open(p, 'w').write(x)` without `close()` silently lost the write.

## [0.1.4] - 2026-03-12

### Fixed
- **`list_detailed` path consistency**: `FileInfo.path` now preserves the caller's queried prefix across all implementations — `list_detailed("src/")` returns `path="src/lib/util.py"`, `list_detailed("/")` returns `path="/src/lib/util.py"`, and `list_detailed(".")` returns `path="src/lib/util.py"`. Previously MountFS stripped the queried prefix and VirtualFS stripped the leading slash for root queries.

## [0.1.3] - 2026-03-08

### Changed
- **Pyodide compatibility**: Minor adjustments for pyodide compat (os.link)

## [0.1.2] - 2026-03-03

### Added
- **ReadOnlyFS**: Wrapper that blocks all write operations with `PermissionError`. Read operations delegate transparently to the wrapped filesystem.
- **MountFS**: Routes filesystem operations to different backing filesystems by path prefix. Supports dynamic mount/unmount, own CWD, list merging at mount boundaries, cross-mount rename, nested mounts, and glob across mounts.

## [0.1.1] - 2026-02-28

### Fixed
- **VFS metadata serialization**: Switched from pickle to JSON
- **stat() on files without metadata**: Returns synthetic metadata instead of KeyError
- **stat() synthetic size**: Use actual file size instead of 0 for files without metadata entries
- **utime**: Updates VFS metadata instead of silently no-oping
- **readlink**: Validates relative symlink targets stay within sandbox root
- **mkdir mode**: Passes mode argument through to IsolatedFS
- **realpath escape fallback**: Return normalized absolute path instead of "/" when path escapes sandbox

### Changed
- **Metadata caching**: Parsed metadata cached in memory to avoid repeated JSON deserialization
- **remove_many**: Batched metadata update instead of one per file
- **connect_fs removed**: Deferred filesystem config moved to agex where it belongs
- **Backing state ownership**: Documented that VFS backing state should be treated as owned by the instance
